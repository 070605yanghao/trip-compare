# 需求主列表

> 全部产品需求的主清单。人写；AI 不主动改需求文本（人要求改时记入 decisions.md）。
> 格式：每个需求一节 `## REQ-NNN — 标题`，下面放完整规格。顺序 = 优先级。
> 状态/功能链接/演化关系在 `requirements-index.md`，不在本文件。

## REQ-001 — 行程对比器 MVP

把多份旅游产品说明书（PDF/TXT）提取为结构化字段，生成一页 HTML 对比矩阵报告。字段包括：天数/晚数、团型、用车、行程路线、住宿、赠送项目、需自理、滑雪、旅拍、定位人群。支持命令行批量输入文件或目录，输出单文件 HTML 与可选 JSON 结构化数据。

## REQ-002 — 四态信息状态与原文依据

每条结论必须带信息状态（明确包含 / 明确不包含 / 表述模糊 / 原文未提及）与原文依据。「没提取到」绝不显示为「不包含」；「独家服务」与「属性差异」必须区分，独家需要双向证据（本品明确包含且其他产品明确不包含）。同一条事实只在一个展示维度出现，去重靠归类不靠删除。赠送/自理/明确不含三种费用语义互斥且在 JSON 中分开存放。

## REQ-003 — 真实说明书加固与线上 Demo 同步

在真实旅行社 PDF（含图片型说明书）上提升鲁棒性：标题提取不拿正文碎片充数；正文提不到天数时可回退文件名并注明来源；人群定位要求定位语境；PDF 硬换行产生的残缺括号途经点不进路线；「没有+抒情句」不被当成「明确不包含」。样品报告与北疆四线路真实报告同步发布到线上 Demo（docs/ + GitHub Pages）。
