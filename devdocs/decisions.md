### D-001 — 四态信息状态模型 (2026-10-16)

**Context:** 早期版本把「没提取到」直接显示为「不包含」，用户会误以为竞对产品明确不提供某项服务。
**Decision:** 引入四态：明确包含（included）/ 明确不包含（excluded）/ 表述模糊（ambiguous）/ 原文未提及（unknown），每条结论附原文依据；未提及项不参与独家项判定。
**Rationale:** 选品场景里「没写」和「写了不含」是两种完全不同的信息，混淆会直接导致错误采购决策。四态 + 依据让人能一眼核实。
**Consequences:** 报告新增状态图例；matrix 里 unknown 显示灰色「未提及」；独家标记要求双向证据。

### D-002 — 去重靠归类不靠删除 (2026-10-16)

**Context:** 「赠送无人机航拍」既是赠送又是旅拍，早期在两行重复展示，显得信息冗余。
**Decision:** 一条事实按 CAT_PRIORITY（滑雪 > 旅拍 > 赠送 > 需自理 > 明确不含 > 包含服务）唯一归属一个展示维度；展示层按主类别过滤，JSON 保留全量条目。
**Rationale:** 删除会丢信息，归类既保证展示干净又保证结构化数据完整，后续任何维度要回溯都拿得到。
**Consequences:** `TripProduct.items_of(dim)` 负责展示层过滤；赠送项目全部落在旅拍/滑雪时，赠送行改为「共 N 项，详情见「X」维度」。

### D-003 — 费用语义互斥与 JSON 字段分离 (2026-10-17)

**Context:** 「滑雪：不含」曾混进 self_pay 字段，「正餐自理」和「骑马自费」被统一标成「明确需自费」，语义错误。
**Decision:** 分类互斥：赠送 > 自费 > 明确不含 > 包含；JSON 里 `self_pay` 只放需自理/自费，`excluded` 单列明确不包含；报告文案区分「明确需自理」「明确需自费」「明确需自理/自费」。
**Rationale:** 「要另外掏钱」和「明确不提供」对采购是两个动作；混在一起会让 JSON 消费者做不出正确筛选。
**Consequences:** schema.py 新增 `excluded` 字段（向后兼容，旧字段不动）；status_label 按条目关键词细分自理/自费。

### D-004 — 展示条数与依据条数一致 (2026-10-17)

**Context:** 报告曾显示 4 个条目却只给 3 条原文依据，截断处不带省略号，住宿摘要断在半个词上。
**Decision:** 展示与依据共用 MAX_SHOW=4，超出时显示「… 共 N 条原文依据」；摘要截断统一补「…」；证据截断用栈式括号检查，不在未闭合括号中间切断；切分子句时先合并括号内的断片。
**Rationale:** 报告的可信度来自「每个字都能对回原文」，截断残缺会破坏信任。
**Consequences:** parser 与 report 各有一层括号保护；测试固定了「依据条数不少于展示条数」「无悬空括号」两条红线。

### D-005 — 真实 PDF 加固策略 (2026-10-18)

**Context:** 用四份真实旅行社说明书跑时发现：图片型 PDF（M1-A）标题被取成正文碎片、定位人群被「单人房费」污染、行程覆盖混入半截括号途经点、「没有超燃群像」这类抒情句被判成「明确不包含」。
**Decision:** 标题行必须有天数且排除费用/说明类行，取不到就回退文件名；人群定位要求句中带定位语境（定位/适合/人群…）；途经点括号未闭合即丢弃；「没有」必须紧跟被否定对象才算否定。
**Rationale:** 真实 PDF 的噪声主要来自扫描件文字层缺失和硬换行，加固瞄准这四类高发错误，而不是泛化正则。
**Consequences:** 文件名兜底时依据注明「文件名：…」；新增 6 项加固测试；「没有+对象」清单需要随新误报扩充。

### D-006 — 引入 claude-dev-system 开发流程 (2026-10-18)

**Context:** 老师分享了一套人机协作开发系统（CLAUDE.md + docs 状态文档 + 漂移校验），项目此前没有成文的流程约束，AI 各会话之间靠口口相传。
**Decision:** 全套引入并适配：流程文档放 `devdocs/`（`docs/` 是 GitHub Pages 发布目录，不能混用）；三道审批闸门映射为 数据模型 / 输出契约 / 报告样式；check-docs-drift.py 适配到本仓库；回填 REQ-001~003、F-001~003 与 D-001~005 作为历史状态。
**Rationale:** 项目已经历三轮「改坏—验收—返修」，问题多出在 AI 擅自扩大范围和状态无记录；这套系统恰好针对这两点。
**Consequences:** 此后功能开发走「规格 → 三闸门 → 实现 → 验收」循环；CLAUDE.md 只有「当前焦点」一节允许 AI 改。
